# 星辰工坊 · 角色清单模板（Character_List_Blueprint）

用于整理不需要独立主角色卡或完整 NPC 卡、但仍具有保留价值的角色。

由角色出场表、实体归并或局部笔记转写而来，输出到 `outputs/SillyTavern角色汇总/`。

角色使用详细清单还是极简清单，应根据角色重要性、材料丰富度、当前主线相关性和 RP 使用价值判断；角色数量只影响是否合并成一个条目，不作为唯一分流标准。

## 填写规则

- 按地域、国家、组织、势力或阵营分类整理。
- 同一角色只能出现在一种清单模式中，不得重复建档。
- 性别、年龄、外貌、当前状态没有依据时标【待核查】，不要编造。
- `Current` 以 PROJECT_CONFIG.md 或用户指定的故事基准时间点为准。
- 与 `{{user}}` 的关系只能来自用户明确指定；关系深刻时写入身份。
- 来源写在 XML 外的“来源附录”，不进入条目正文。
- 外层标签使用 `NPC_Detail_${分类标识}` 或 `NPC_List_${分类标识}`，确保现有角色归并脚本可以识别。

## 详细清单模式

### 适用场景

- 材料能够支撑身份、外貌、性格、当前状态和活动地点。
- 角色具有一定剧情、关系或世界观价值。
- 但材料不足以生成完整 NPC 卡。
- 即使角色数量较多，也应按分类拆分，不得仅因人数较多而降为极简清单。

### 内容要求

- 每角色约 100–200 个中文字符。
- `Basic`：性别、年龄、身份、1–2 句外貌特征、1–2 句性格核心。
- `Current`：当前处境、正在做的事或短期目标，不写人生履历。
- `Appear`：常出没地点、所属驻地或稳定行踪。
- 没有稳定行踪时写【待核查】，不要把单次出场地点写成长期活动规律。

### 输出结构

````xml
<NPC_Detail_${分类标识}>
条目名称：角色详表 - ${分类名}
关键词：${分类名},${角色名及经核验别名}
插入位置：角色定义之后
插入顺序：${建议 250-450}
激活策略：关键词

${分类名}:

${角色名1}:
  Basic: ${性别，年龄，身份，外貌简述，核心性格特征}
  Current: ${当前所处情况／正在做的事／短期目标}
  Appear: ${常出没地点／所属驻地／行踪规律}

${角色名2}:
  Basic: ${性别，年龄，身份，外貌简述，核心性格特征}
  Current: ${当前所处情况／正在做的事／短期目标}
  Appear: ${常出没地点／所属驻地／行踪规律}
</NPC_Detail_${分类标识}>
````

## 极简清单模式

### 适用场景

- 角色具有保留价值，但材料主要只能支撑身份、职能和一个核心记忆点。
- 角色戏份较少，缺乏独立行动、关系或语料。
- 角色对项目当前时间点、主线剧情或 RP 场景作用较低。
- 用户要求极度精简。
- 角色数量较多时可以合并，但人数不是选择极简模式的唯一依据。

### 内容要求

- 每角色一行，原则上控制在 50 个中文字符以内。
- 判词应体现性格核心矛盾、行为倾向或鲜明记忆点。
- 不写“性格复杂”“十分重要”“神秘莫测”等空泛评价。
- 若角色与 `{{user}}` 关系深刻，应在身份中体现。
- 性别或年龄不明时标【待核查】，不得猜测。

### 输出结构

````xml
<NPC_List_${分类标识}>
条目名称：角色清单 - ${分类名}
关键词：${分类名},${角色名及经核验别名}
插入位置：角色定义之后
插入顺序：${建议 300-500}
激活策略：关键词

${分类名}:
- ${姓名}，${性别}，${年龄}岁，${身份／职能}，${一句话判词}
- ${姓名}，${性别}，${年龄}岁，${身份／职能}，${一句话判词}
</NPC_List_${分类标识}>
````

## 来源附录

```markdown
## 来源附录

- ${角色名1}：${来源篇目／章节／局部笔记}；待核查：${无／具体缺口}
- ${角色名2}：${来源篇目／章节／局部笔记}；待核查：${无／具体缺口}
```
