# 星辰工坊世界书条目模板

本模板用于生成可导入/可改写为星辰工坊世界书条目的结构。依据（项目内存档，无需星辰工坊预设）：
- `references/星辰工坊规范/什么是世界书.yaml`
- `references/星辰工坊规范/创世-世界书规范.txt`

核心规则：
- 世界书采用“🔵常驻总览索引 → 可选的🟢次级骨架 → 🟢关键词详情条目”的分层激活链。
- 每个🟢关键词条目的主关键词，必须出现在其直接母条目的条目内容中；直接母条目可以是🔵常驻总览，也可以是承担次级骨架职责的🟢条目。若直接母条目为🟢条目，其主关键词必须沿母子链追溯到🔵常驻根条目。蓝灯只需提及直接子条目，不必包含所有后代关键词。
- 所有世界书条目默认勾选“不可递归”和“防止进一步递归”；只有用户明确要求时才可取消对应勾选。
- 只有“条目内容”会进入上下文；条目名称、关键词、插入位置、插入顺序、激活策略是管理/触发元数据。
- 【世界内视角铁律】条目内容必须以"世界内事实"的客观视角书写，禁止元叙事：不出现"原著/小说/作者/本篇/据原文/被写作"等字眼，不要用篇目或章节标题当事件名（如"泉先儿事件"），改为描述事件本身或用世界内称呼。
- 宏观设定使用客观陈述；微观生活、地点、关系可加入具象细节和互动影响。
- 来源**不写进条目内容**（会污染 RP 上下文）；统一记录在世界书输出文件 `## 生成说明与检查` 的「来源对照」表里。

## 推荐条目块格式

```xml
<{{语义标签名}}>
条目名称：{{分类}} - {{条目名}}
关键词：{{关键词1}},{{关键词2}},{{别名}},{{相关触发词}}
插入位置：角色定义之前 / 角色定义之后 / @D4 system
插入顺序：{{数字}}
激活策略：常驻 / 关键词
不可递归：是
防止进一步递归：是

条目内容：
{{YAML或PList结构化内容——纯世界内客观陈述，不含来源、不含元叙事}}
</{{语义标签名}}>
```

## 🔵蓝灯常驻总览条目

适用：世界基石、运行法则、空间骨架、组织/地点/物种总览。

推荐配置：
- 激活策略：常驻
- 插入位置：角色定义之前
- 插入顺序：
  - 世界基石：0-50
  - 运行法则：50-100
  - 空间骨架/总览索引：100-200

内容要求：
- 写清“这是什么”。
- 在条目内容中用自然叙述或 PList `has(...)` 明确提及需要展开的地点、组织、物种、物品、NPC、事件关键词。
- 不要把所有细节塞进蓝灯；蓝灯负责搭骨架和提供触发链。
- 字数建议 300-600 字，或使用 PList 速写压缩信息。
- 不要写“需要展开的关键词包括”“index_keywords”“本条目索引”等元说明；关键词应像世界内容的一部分自然出现。

```xml
<世界观总览>
条目名称：世界 - {{作品/世界名}}总览
关键词：{{作品名}},{{世界名}},{{核心主题词}}
插入位置：角色定义之前
插入顺序：10
激活策略：常驻
不可递归：是
防止进一步递归：是

条目内容：
world_name: {{作品/世界名}}
era: {{时代背景}}
theme_tags: {{主题1}} | {{主题2}} | {{主题3}}
tone: {{叙事气质}}
core_conflict: {{核心冲突}}

{{客观描述世界基石。必须自然提及后续绿灯条目的关键词，例如主要城市、组织、物种、规则、关键地点。}}

空间与势力骨架：
 [{{地点A}}({{特色}}): {{特征1}}, {{特征2}}, has({{子地点1}}, {{组织A}}, {{物品A}}), {{互动影响}}]
 [{{地点B}}({{特色}}): {{特征1}}, {{特征2}}, has({{物种A}}, {{事件A}}, {{关系A}}), {{互动影响}}]
</世界观总览>
```

## PList 速写格式

适用：地点设施、物品类别、组织架构、城市分区、势力总览。

```txt
[实体名称(别名/特色): 特征1, 特征2, has(子项1, 子项2, 子项3), 其他描述性特征]
```

要求：
- 每个实体一行。
- `has()` 内的子项名称可作为下层🟢条目的关键词。
- 每个实体建议 30-80 字。

## 🟢绿灯详细条目

适用：单一地点、组织、物品、NPC、事件、物种、具体规则、角色关系、日常生活。

推荐配置：
- 激活策略：关键词
- 插入位置：角色定义之后
- 插入顺序：
  - 地点/组织/物种详情：150-300
  - 角色相关/关系/日常：200-400
  - 特殊物品/历史事件/回忆：400-600

内容要求：
- 核心定义：是什么，基本信息。
- 关键特征：有何特点，用具象细节表现，不堆抽象概念。
- 关联要素：与角色、地点、组织、剧情的关系。
- 互动影响：它会如何影响角色对话、行动、冲突或选择。
- 字数建议 200-500 字。

```xml
<location_{{地点名}}>
条目名称：地点 - {{地点名}}
关键词：{{地点名}},{{别名}},{{所属区域}},{{相关人物或设施}}
插入位置：角色定义之后
插入顺序：180
激活策略：关键词
不可递归：是
防止进一步递归：是

条目内容：
location_name: {{地点名}}
type: {{地点类型}}
located_in: {{所属区域}}
related_characters: [{{角色A}}, {{角色B}}]

{{用具体场景和感官细节描述地点，并说明这里会怎样影响角色互动、行动路线或信息流动。}}

core_areas:
  [{{区域A}}: {{特征1}}, {{特征2}}, has({{子地点1}}, {{子地点2}}), {{互动影响}}]
  [{{区域B}}: {{特征1}}, {{特征2}}, has({{子地点3}}, {{子地点4}}), {{互动影响}}]

</location_{{地点名}}>
```

## 日常生活/关系条目

适用：亲密关系、同居生活、长期搭档、师徒、家族关系、组织内部日常。

```xml
<daily_life_{{关系或场景名}}>
条目名称：日常 - {{关系或场景名}}
关键词：{{角色A}},{{角色B}},{{关系名}},{{共同地点}}
插入位置：角色定义之后
插入顺序：320
激活策略：关键词
不可递归：是
防止进一步递归：是

条目内容：
relationship_state: {{当前关系定位}}
living_space: {{生活空间或共同场景}}
daily_roles: {{分工/习惯}}
conflict_points: {{日常摩擦或禁忌}}
rituals: {{固定仪式或习惯}}

{{用具体物品、动作、对话习惯呈现关系质感，不写空泛的“关系很好”。}}

</daily_life_{{关系或场景名}}>
```

## 禁止项

- 不要创建主关键词没有被直接母条目提及，或无法沿母子链追溯到蓝灯根条目的🟢悬空条目。
- 不要过度使用🔵常驻模式。
- 不要在条目内容中写“本条目介绍……”这类元叙述。
- 不要把单篇特例写成全局规则。
- 不要编造原文没有证据的信息。
- 不要把关键词写得过泛，导致误触发。
