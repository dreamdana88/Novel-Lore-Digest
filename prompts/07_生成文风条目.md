# 生成蜃灵文风条目

仅当 `PROJECT_CONFIG.md` 中 `是否生成文风条目：是` 时执行本阶段。
若为「否」，不得新建或更新 `outputs/文风条目.md`，也不得把它列为完成门槛。

## 读取范围

1. `PROJECT_CONFIG.md`，确认作品名、作者、分析重点和特别注意。
2. `workspace/notes/` 中已完成的局部笔记。
3. `workspace/entities/` 中与叙述视角、人物语言、场景描写有关的归并资料。
4. 必要时回读 `workspace/source/` 中具有代表性的原文片段。

禁止联网补充作者评论或凭印象概括作者风格。所有判断只能依据项目原文；
每项分析证据须记录来源文件、篇目或章节。不确定之处标注【待核查】。

## 分析方法

先在工作过程中完成四维拆解，再把结论转为白话、可执行的写作指令：

1. **语感腔调**：长短句比例、停顿习惯、词汇取向、口语或文学化程度、文字密度。
2. **叙事偏好**：动作、对话、内心和环境的镜头重心；主要感官通道；心理处理与叙述距离。
3. **对话规则**：对话是否独立成段、引导词密度、叙述与对白的衔接、潜台词与留白程度。
4. **核心禁忌**：原文明显回避的表达方式，以及模仿时最容易出现的跑偏方向。

每个维度至少核对两处不同位置的原文证据，避免把单篇特例上升为全书规则。
分析报告不单独输出；证据集中写入成品末尾的「来源附录」。

## 写入文件

生成 `outputs/文风条目.md`，条目正文（含示例、不含来源附录）控制在约 800 字，使用以下结构：

```markdown
## 文风·{作品名或简洁风格名}

{一句话定调：说明这种文风读起来是什么感觉}

### 语感腔调

{白话、可执行的句式节奏与词汇指令}

### 叙事偏好

{镜头重心、感官通道、心理处理和叙述距离指令}

### 对话规则

{对白分段、标签、潜台词和留白指令}

### 禁用项

{最容易跑偏的方向；具体说明不要怎样写}

### 示例

{从原文中选择一段 300-500 字代表性片段，优先包含对话与叙述；正文中不注明出处}

## 来源附录

- {结论或示例对应的来源文件 / 篇目 / 章节}
```

## 质量检查

- 正文是可直接供 SillyTavern / 蜃灵使用的提示词，不是文体学论文。
- 指令具体可操作，避免只写“细腻”“有氛围”等空泛形容。
- 四个维度逻辑一致，并有多处原文证据支撑。
- 示例必须逐字来自项目原文，不得改写或拼接；找不到合适片段时写【待选取示例】，不得编造。
- 来源附录与正文分离，确保正文可独立使用。
