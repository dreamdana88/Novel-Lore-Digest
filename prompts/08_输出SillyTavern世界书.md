请基于 workspace/entities/ 和已完成的局部笔记，生成 outputs/SillyTavern世界书.md。

生成结构必须遵循星辰工坊世界书规范，参考：
- templates/worldbook-entry-template.md
- templates/worldbook-output-template.md
- references/星辰工坊规范/什么是世界书.yaml
- references/星辰工坊规范/创世-世界书规范.txt

核心要求：
0. 【世界内视角铁律】可导入条目块的「条目内容」必须以"世界内"的客观视角书写，禁止任何元叙事：
   - 不出现"原著/小说/作者/本篇/本章/据原文/被写作/设定为"等字眼。
   - 不要用篇目或章节标题当事件名（如"泉先儿事件"）；改为描述事件本身或用世界内称呼。
   - 来源篇目不写进条目内容，统一放到 `## 生成说明与检查` 的「来源对照」里。
1. 只使用已归并、证据明确的稳定设定，不要编造原文没有的信息。
2. 按“🔵常驻总览索引 → 🟢关键词详情条目”的二级结构生成世界书。
3. 每个🟢关键词条目的关键词，必须至少出现在一个🔵常驻总览条目的条目内容中，避免悬空条目。
4. 蓝灯总览用于世界基石、运行法则、空间骨架和索引，不要塞入过量细节。
5. 绿灯详情用于地点、组织、物种、物品、NPC、事件、具体规则、角色关系和日常生活。
6. 条目内容应具象、简洁、可用于角色互动；不要写成百科论文。
7. 宏观设定保持客观陈述；微观生活、地点和关系条目可加入画面感、感官细节和互动影响。
8. 可使用 YAML 结构和 PList 速写格式，例如 `[地点名(特色): 特征1, 特征2, has(子项1, 子项2), 互动影响]`。
9. 禁止把单篇偶发设定误写成全局规则；单篇特例必须标注为特例或【待核查】。
10. 来源不写进条目内容（避免污染 RP 上下文）；统一在 `## 生成说明与检查` 的「来源对照」表里用 条目名→来源篇目 的形式记录，方便复查。

条目格式必须使用以下星辰工坊导入友好的 XML 块（条目内容里**不含来源、不含元叙事**）：

```xml
<{{语义标签名}}>
条目名称：{{分类}} - {{条目名}}
关键词：{{关键词1}},{{关键词2}},{{别名}},{{相关触发词}}
插入位置：角色定义之前 / 角色定义之后 / @D4 system
插入顺序：{{数字}}
激活策略：常驻 / 关键词

条目内容：
{{YAML结构、PList速写或自然段内容——纯世界内客观陈述}}
</{{语义标签名}}>
```

插入位置与顺序建议：
- 世界基石：常驻，角色定义之前，Order 0-50。
- 运行法则：常驻，角色定义之前，Order 50-100。
- 空间骨架/总览索引：常驻，角色定义之前或之后，Order 100-200。
- 地点/组织/物种详情：关键词，角色定义之后，Order 150-300。
- 角色关系/日常生活：关键词，角色定义之后，Order 200-400。
- 特殊物品/历史事件/回忆：关键词，角色定义之后，Order 400-600。
- @D 深度位置只用于真正需要即时响应的高优先级状态或临时规则，默认不要使用。

输出文件结构必须如下：

1. `# SillyTavern 世界书`
2. `## 可导入条目块`
   - 这里只放可被星辰工坊世界书管理器扫描导入的 XML 条目块。
   - 不要在本节夹杂解释文字、Markdown 表格、代码围栏或检查说明。
   - 每个条目块之间只用空行分隔。
3. `## 生成说明与检查`
   - `### 生成说明`：说明使用星辰工坊规范、蓝灯/绿灯结构和来源原则。
   - `### 激活链检查`：用表格列出每个绿灯条目、关键词、被哪个蓝灯条目提及、状态。
   - `### 来源对照`：用表格列出 条目名 → 来源篇目/章节/局部笔记（来源只放这里，不进条目内容）。
   - `### 待核查`：列出证据不足、可能悬空、单篇特例误归并等问题。

导入要求：
- `## 可导入条目块` 中的内容应能直接复制到 SillyTavern 聊天，再由星辰工坊世界书管理器扫描导入。
- 给人看的解释、检查表和待核查内容只能放在 `## 生成说明与检查` 下。
